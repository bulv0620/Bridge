# 局域网共享与剪贴板语义

本文记录当前局域网发现、文件传输和剪贴板共享协议。当前协议面向受信任的本地网络，但尚未提供
设备认证或传输加密，不能描述为安全配对或端到端加密。

## 服务启停

- `lanDiscovery` 关闭时，不启动 UDP 发现和 HTTP 共享服务。
- 启用后，UDP 和 HTTP 服务共同启动。
- 默认 UDP 端口为 `9520`，HTTP 端口为 `9521`。
- 默认广播间隔为 1000 ms。
- 当前能力包括 `file-push-v2` 和 `clipboard`，由用户分别启用。
- 已有配置中的 `file-push` 在初始化时迁移为 `file-push-v2`。新版不广播或接受旧文件传输
  能力。

改变端口、监听地址、默认启用状态或服务拆分方式属于安全边界变化。

## UDP 发现协议

设备通过 IPv4 网卡的广播地址发送 JSON：

```json
{
  "v": 1,
  "type": "announce",
  "device": {
    "id": "persistent-device-id",
    "name": "device-name",
    "platform": "darwin"
  },
  "services": {
    "udp": 9520,
    "http": 9521,
    "cap": ["file-push-v2", "clipboard"]
  },
  "state": {},
  "ts": 0
}
```

- `v` 当前固定为 `1`。
- `announce` 表示在线，`bye` 表示主动离线。
- 本机通过持久化 `deviceId` 排除自己的广播。
- 超过 2 个广播间隔未收到更新时标记为 `stale`。
- 超过 5 个广播间隔时从在线列表移除。
- 设备 IP 取自 UDP 数据包来源地址，而不是消息正文。

当前 `trusted` 字段固定为 `false`，没有配对、信任建立或身份验证流程。

## 文件发送

发送端流程：

1. 用户选择或拖入 1 至 256 个普通文件。preload 将真实 `File` 对象登记到主进程，renderer 只
   保存不透明选择 ID 和文件名、大小、MIME 等显示元数据。目录或不可读条目会被拒绝并清空本次
   候选列表，不影响紧接着进行的合法选择。已选摘要显示文件数和总大小，详情弹层中可以在发送前
   单独移除文件；移除后主进程会登记一个不含该文件的新选择并释放旧选择。
2. 用户点击声明 `file-push-v2` 能力的在线设备。
   UI 立即切换到 Sending。
3. 主进程从自身发现状态解析目标，消费一次选择 ID，并向接收端
   `POST /api/file-batches` 发送协议版本、发送设备和整批文件元数据。
4. 接收端校验整批元数据，显示并聚焦主窗口，在原生确认出现前进入共享空间，由用户确认一次。
   批准后 UI 切换到 Receiving，并返回接收端批次 ID 以及每个文件各自的一次性上传令牌。
5. 发送端主进程最多并发上传 3 个文件，通过
   `PUT /api/file-batches/:batchId/files/:fileId` 流式发送。令牌放在 `Authorization`
   请求头中，不进入 URL、renderer 状态或日志。
6. 主进程通过 `sending-list` 和 `sent-list` 更新进度与终态。用户可以单独取消已开始的文件；
   一个文件失败或取消不影响同批其他文件。

发送任务和结果列表只保存在当前运行周期的主进程内存中，并通过只读 RemoteRef 向 renderer
展示；renderer 不回写任务快照。删除 Sent 历史通过按任务 ID 的显式 IPC 完成，重启后全部消失。

## 文件接收

接收端只有在本地启用 `file-push-v2` 时才接受请求。批次必须满足：

- JSON body 不超过 256 KiB，每批包含 1 至 256 个文件。
- 文件 ID 在批内唯一，大小为非负安全整数，整批总大小不能溢出安全整数。
- 文件名必须是 UTF-8 不超过 255 bytes 的单个 basename，不得包含控制字符、NUL、`/` 或
  `\`；Windows 还拒绝非法字符、保留设备名和结尾空格/句点。
- 设备 ID、设备名、MIME 和文件 ID 必须是有界字符串。

非法批次不会显示确认。合法批次进入有界且串行的原生确认队列；队列同时最多容纳 3 个批次，
超出时返回忙碌。确认对话框显示来源设备名、文件数、总大小和最多 5 个文件名，整批只确认一次。

用户拒绝时不创建授权或文件。用户接受后：

- 每个文件获得绑定批次、文件和请求来源 IP 的随机令牌。令牌只能开始一次，未开始时 10 分钟
  过期；错误来源、错误路由、重放或并发使用在创建文件前拒绝。
- 上传必须提供与批准大小完全相同的 `Content-Length`，接收端还会独立计算实际字节数。缺少、
  非法、过长或过短均失败。
- 内容只写入下载目录内独占创建的 `.bridge-transfer-<uuid>.part` 临时文件。成功后以
  “目标不存在才创建”的方式提交；同名文件继续使用 `name (1).ext`、`name (2).ext` 递增，永不
  覆盖现有文件。
- 取消、断线、长度不符、服务停止或写入错误会删除临时文件并产生对应终态。超过 24 小时且能由
  严格文件名规则确认属于 Bridge 的遗留临时文件会在服务启动时清理。
- 接收进度和结果通过主进程只读的 `receiving-list`、`received-list` 提供给 renderer，避免并发
  完成时旧 UI 快照覆盖较新的结果。删除 Received 历史通过按任务 ID 的显式 IPC 完成，重启后
  全部消失。

删除任务记录只删除 UI 列表项，不删除已经接收的文件。

零字节文件是合法文件；完成时进度为 100%，计算过程不得产生 `NaN` 或无限值。

## 文件协议兼容

- UDP 发现协议仍为版本 1，剪贴板能力和 endpoint 不变。
- 新文件协议固定为版本 2，并使用 `file-push-v2` 能力。
- 新版与只声明旧 `file-push` 的版本可以发现彼此，在共同启用 `clipboard` 时仍能共享剪贴板，
  但文件发送入口不可用。
- 新版不提供 `POST /api/upload/request`、`POST /api/upload/:uploadId` 或任何旧协议降级链路。
- 从新版降级到旧版后，旧版可能把文件接收开关显示为关闭；测试期接受这一兼容代价。

## 剪贴板共享

本地启用 `clipboard` 后，广播状态会包含当前剪贴板版本和 MIME。双方都声明该能力且发现新版本时，
接收方从对方的 `GET /api/clipboard/:v` 拉取内容。

- 小文本可以直接保存在内存记录中。
- 图片或较大内容使用应用 userData 下的临时文件。
- 自定义 `clipboard:` 协议只允许读取 userData 的 `clipboard` 子目录。
- 当前剪贴板历史是运行时状态，不持久化。

剪贴板内容可能包含敏感信息，因此禁止记录完整文本、HTML、图片数据或系统剪贴板路径。

## 当前安全边界与已知限制

以下是理解当前实现必须知道的限制，不表示这些行为是长期目标：

- UDP 声明和 HTTP 请求没有设备认证，字段可以被同网段主机伪造。
- HTTP 传输未使用 TLS，也没有内容级加密。
- HTTP server 不提供 CORS 允许头。文件发送已移到主进程，不依赖 renderer 跨域请求。
- 接收请求中的文件名、大小、设备信息和上传 body 都来自不可信网络。
- 文件传输强制校验声明与实际长度，但没有内容哈希、磁盘配额或单文件大小限制。
- 文件名、下载目录边界、独占临时文件和不覆盖提交共同限制路径风险；不能只依赖发送端提供的
  浏览器文件名。
- 上传令牌绑定来源 IP，但当前没有设备身份认证；同网段可观察 HTTP 的攻击者仍可能读取文件或
  令牌。
- 在线状态只代表近期收到声明，不代表设备可信。

涉及上述任一项的修复或能力新增属于 L 级安全任务，应使用恶意输入测试，而不只是正常设备联调。

## 协议变更要求

改变消息字段、HTTP endpoint、能力名称或默认行为时，Spec 必须说明：

- 协议版本和向后兼容策略。
- 新旧版本设备相遇时的行为。
- 身份、授权、隐私和重放风险。
- 超时、取消、断线和部分文件的处理。
- Windows、macOS 和 Linux 的文件名与路径差异。
- 日志允许记录和必须脱敏的字段。
