# 局域网共享与剪贴板语义

本文记录当前局域网发现、文件传输和剪贴板共享协议。当前协议面向受信任的本地网络，但尚未提供
设备认证或传输加密，不能描述为安全配对或端到端加密。

## 服务启停

- `lanDiscovery` 关闭时，不启动 UDP 发现和 HTTP 共享服务。
- 启用后，UDP 和 HTTP 服务共同启动。
- 默认 UDP 端口为 `9520`，HTTP 端口为 `9521`。
- 默认广播间隔为 1000 ms。
- 当前能力包括 `file-push` 和 `clipboard`，由用户分别启用。

改变端口、监听地址、默认启用状态或服务拆分方式属于安全边界变化。

## UDP 发现协议

设备通过 IPv4 网卡的广播地址发送 JSON：

```json
{
  "v": 1,
  "type": "announce",
  "device": {
    "id": "persistent-device-id",
    "name": "device-name",
    "platform": "darwin"
  },
  "services": {
    "udp": 9520,
    "http": 9521,
    "cap": ["file-push", "clipboard"]
  },
  "state": {},
  "ts": 0
}
```

- `v` 当前固定为 `1`。
- `announce` 表示在线，`bye` 表示主动离线。
- 本机通过持久化 `deviceId` 排除自己的广播。
- 超过 2 个广播间隔未收到更新时标记为 `stale`。
- 超过 5 个广播间隔时从在线列表移除。
- 设备 IP 取自 UDP 数据包来源地址，而不是消息正文。

当前 `trusted` 字段固定为 `false`，没有配对、信任建立或身份验证流程。

## 文件发送

发送端流程：

1. 用户选择一个文件。
2. 用户点击声明 `file-push` 能力的在线设备。
3. renderer 向接收端 `POST /api/upload/request` 发送文件元数据。
4. 接收端返回 `allowed: true` 和 `uploadId` 后，发送端向
   `POST /api/upload/:uploadId` 上传原始文件内容。
5. renderer 根据上传进度更新发送任务；用户可以请求中止发送。

发送任务和结果列表只保存在 renderer 内存中，重启后消失。

## 文件接收

接收端只有在本地启用 `file-push` 时才接受请求。每个请求都会显示原生确认对话框，其中包含：

- 对方提供的文件名。
- 文件大小。
- 对方提供的设备名称。

用户接受后：

- 文件保存在配置的下载目录。
- 同名文件不会被覆盖，而是使用 `name (1).ext`、`name (2).ext` 递增。
- 接收进度和结果通过 RemoteRef 提供给 renderer。
- 接收结果仅保存在当前主进程内存中。

删除任务记录只删除 UI 列表项，不删除已经接收的文件。

## 剪贴板共享

本地启用 `clipboard` 后，广播状态会包含当前剪贴板版本和 MIME。双方都声明该能力且发现新版本时，
接收方从对方的 `GET /api/clipboard/:v` 拉取内容。

- 小文本可以直接保存在内存记录中。
- 图片或较大内容使用应用 userData 下的临时文件。
- 自定义 `clipboard:` 协议只允许读取 userData 的 `clipboard` 子目录。
- 当前剪贴板历史是运行时状态，不持久化。

剪贴板内容可能包含敏感信息，因此禁止记录完整文本、HTML、图片数据或系统剪贴板路径。

## 当前安全边界与已知限制

以下是理解当前实现必须知道的限制，不表示这些行为是长期目标：

- UDP 声明和 HTTP 请求没有设备认证，字段可以被同网段主机伪造。
- HTTP 传输未使用 TLS，也没有内容级加密。
- HTTP server 当前启用通用 CORS。
- 接收请求中的文件名、大小、设备信息和上传 body 都来自不可信网络。
- 当前协议没有完整性哈希、预期长度强制校验、配额或单文件大小限制。
- 接收路径必须持续接受路径穿越审查；不能仅依赖 renderer 发送的浏览器 `File.name`。
- `uploadId` 是接收授权凭证，但当前没有额外绑定发送设备身份。
- 在线状态只代表近期收到声明，不代表设备可信。

涉及上述任一项的修复或能力新增属于 L 级安全任务，应使用恶意输入测试，而不只是正常设备联调。

## 协议变更要求

改变消息字段、HTTP endpoint、能力名称或默认行为时，Spec 必须说明：

- 协议版本和向后兼容策略。
- 新旧版本设备相遇时的行为。
- 身份、授权、隐私和重放风险。
- 超时、取消、断线和部分文件的处理。
- Windows、macOS 和 Linux 的文件名与路径差异。
- 日志允许记录和必须脱敏的字段。
