# 文件同步语义

本文记录当前代码实际执行的同步语义。它是修改比较、方向、删除、覆盖和冲突行为时的长期基线。
除非已批准 Spec 明确改变，本文件中的行为必须保持。

> 警告：同步会直接删除或覆盖端点中的文件，目前没有回收站、事务日志或自动回滚。验证只能使用
> 为测试创建的临时目录或专用测试端点。

## 端点与方向

- 左侧端点固定称为 source。
- 右侧端点固定称为 destination。
- `toRight`：让 destination 的该路径采用 source 状态。
- `toLeft`：让 source 的该路径采用 destination 状态。
- `ignore`：本轮不改变该差异文件。
- 目录自身没有 resolution，只聚合子文件方向计数。

方向不是简单的“复制”：

- `toRight` 时，如果 destination 已存在该文件，先删除 destination 文件；source 存在时再复制。
- `toLeft` 时，如果 source 已存在该文件，先删除 source 文件；destination 存在时再复制。
- 因而当来源侧不存在时，相应方向表示删除另一侧文件。

## 当前相等与差异判定

比较按相对路径逐目录进行，当前规则如下：

1. 同一目录内，以“文件/目录类型 + 文件名”作为匹配键。
2. 两侧同名、同类型的普通文件，只要大小相同就视为相同，不比较时间戳和内容。
3. 同名、同类型但大小不同的文件作为两侧都存在的差异。
4. 目录即使两侧都存在也会继续向下遍历。
5. 同名文件与目录使用不同匹配键，会作为两个独立差异项处理。
6. 比较是区分大小写还是不区分大小写，受存储后端列出的名称和平台文件系统影响，应用没有额外
   统一大小写规则。

这意味着“同大小但内容不同”的文件当前不会出现在差异列表中；文档和 UI 不应声称 Bridge
使用内容哈希或总能识别内容冲突。

## 策略决策表

下表针对普通文件。`source`、`destination` 表示该侧存在对应文件。

| 文件状态            | mirror                             | incremental                        | twoWay                        |
| ------------------- | ---------------------------------- | ---------------------------------- | ----------------------------- |
| 仅 source 存在      | `toRight`：复制到 destination      | `toRight`：复制到 destination      | `toRight`：复制到 destination |
| 仅 destination 存在 | `toRight`：从 destination 删除     | `ignore`：保留 destination         | `toLeft`：复制到 source       |
| 两侧存在但大小不同  | `toRight`：source 覆盖 destination | `toRight`：source 覆盖 destination | `ignore`：默认不处理          |
| 两侧同名同大小      | 不进入差异列表                     | 不进入差异列表                     | 不进入差异列表                |

用户可以在比较后逐项改变 resolution。改变策略会重新计算当前所有普通文件的默认 resolution，
覆盖用户此前的逐项选择。

## 忽略规则

用户配置的是文件夹名称列表：

- 遍历任意层级时，只要目录名精确出现在列表中，就跳过整个目录。
- 当前 UI/数据模型不表达“仅忽略某一相对路径”的规则。

应用还按平台内置忽略项：

- macOS：名称中包含 `.DS_Store`、`.app` 或 `.asar`。
- Windows：名称中包含 `desktop.ini` 或 `.asar`。
- 其他平台：当前没有内置忽略项。

内置规则使用名称包含匹配，而不是严格相等。改变匹配方式会影响同步结果，必须通过 Spec。

## 目录行为

- 差异树中的目录用于组织和汇总子文件。
- 没有差异子项的目录会从结果中清除。
- 当前同步执行跳过目录项，不显式创建或删除空目录。
- 因而空目录不是当前同步结果的一部分，不能承诺镜像后目录结构在空目录层面完全一致。

## 比较生命周期

1. 开始比较时清空旧差异和统计。
2. 两个端点先由各自存储引擎校验。
3. `SyncSession` 使用栈逐目录扫描，并将结果保存在内存 `DiffStore`。
4. renderer 按父节点懒加载差异树。
5. 完成或停止后断开两个存储引擎。

停止比较会设置协作式 stop flag。它不会强制中断正在等待的单次网络/文件系统操作；该操作返回后，
循环才停止。已生成的部分差异和统计可能保留在当前会话中。

## 同步生命周期

1. 同步前再次校验端点。
2. 按 `DiffStore` 当前尾部顺序逐项处理。
3. 每处理一个普通文件，更新传输字节和完成数量并向 renderer 推送。
4. 已处理项从内存差异存储中删除。
5. 完成、失败或停止后断开存储引擎。

当前不提供：

- 整批事务性。
- 删除后的回收站。
- 写入临时文件后原子替换的统一保证。
- 失败后的自动重试、恢复点或回滚。
- 比较完成到同步开始之间的文件变化检测。

停止同步同样是协作式的，不能保证中断正在传输的单个文件。

## 存储引擎共同契约

所有端点通过 `StorageEngine` 提供：

- 校验和断开。
- 列目录、读取/写入、流式读写。
- 删除、存在性、创建目录。
- 元数据与容量查询。

新增存储引擎必须通过 `StorageEngineFactory` 创建，并明确说明其路径格式、时间精度、元数据能力、
删除语义、流式写入完成语义和容量支持。后端能力不足时必须显式降级，不能伪造保证。

当前容量能力如下：

- Local 使用运行时文件系统 API 查询所选目录所在文件系统的总容量和已用容量。
- FTP/FTPS 和 S3/S3 兼容服务不提供统一可靠的容量能力，明确返回不支持；应用不会遍历文件或
  对象估算容量。
- 容量查询失败只影响辅助容量展示，不影响端点校验、比较或同步。容量结果是运行时状态，不属于
  持久化端点配置。

## 修改本语义的要求

以下变化必须使用 L 级 Spec：

- 相等/冲突判定（时间戳、哈希、大小写等）。
- 策略决策表中的任意单元格。
- 删除、覆盖、执行顺序、失败恢复或原子性。
- 忽略规则和符号链接行为。
- 空目录处理。
- 比较或同步期间并发修改文件的处理。

Spec 必须给出覆盖“仅左、仅右、双方不同、同名同大小、文件/目录类型冲突、失败、停止”的验收
矩阵，并分别验证适用的 Local、FTP 和 S3 组合。
